# H3 2-box 배포 (spark1 + spark2-p1-r0)

실행 순서는 `h3.instruction.txt` (한 줄에 명령어 하나씩, 왼쪽 40칸=spark1 / 40칸 지점부터=spark2, 위→아래).
두 박스 모두 계정 `user1`, 디렉토리 구조 동일 (`~/src/inference-engines`,
`~/git/*`, `~/tools/vllm-omni`, `~/models/MiniMax-H3`, `~/data/minimax-h3-comfyui`).

## 1. 토폴로지

| 역할 | 호스트 | 담당 | 포트 | 상주 메모리(추정) |
|---|---|---|---|---|
| vLLM 박스 | spark1 | FL2VA ↔ Ref2VA 교대 서빙 | 8000 | FP8 ~70G |
| Comfy 박스 | spark2-p1-r0 (CX7 192.168.102.2) | ComfyUI 전용 | 8188 (직통) | ~45G |
| 진입점 | spark1 | proxy-8188 → CX7 IP로 전달 | 8188 (proxy) | — |

원칙: **박스당 single-tenant 유지, 박스끼리는 동시 가동**. TP 분산 없음
(Spark 간 NVLink가 없어 이더넷 TP는 실용성 없음. 각 서빙은 박스 1대에 통째로).

`h3.cluster.env` (single source of truth, `proxy-up.sh`가 source):

| 변수 | 값 | 용도 |
|---|---|---|
| SPARK_VLLM_HOST | spark1 | 문서용 |
| SPARK_COMFY_HOST | spark2-p1-r0 | resolve → CX7 IP 확정 |
| CX7_SUBNET | 192.168.102. | 대역 가드 (벗어나면 중단) |
| SPARK_COMFY_IP | (미지정=자동) | 강제 지정 시 resolve 생략 |
| H3_PORT / COMFY_PORT / PROXY_LISTEN | 8000 / 8188 / 8188 | 포트 |

## 2. 전제 (충족 확인됨)

- 양쪽 OS·nvidia-smi·docker 정상, 동일 계정/디렉토리 구조
- `spark2-p1-r0` → 192.168.102.2 resolve 확인 (`getent hosts`)
  (`spark2` 단독은 미확인, `spark2.local`=192.168.1.212 mgmt LAN이므로 사용 금지)
- spark1 디스크 851G 여유 (FL2VA+Ref2VA 270G 가능)

## 3. 프록시 원안 검토 → 수정 적용

제시된 `docker run ... nginx -g 'daemon off; events {} http {...}'`는 그대로 실행하면
실패한다. 3가지 문제와 수정 (`infra/dgx-spark-1/service/nginx/proxy-up.sh`에 반영, `nginx -t` 통과 확인):

1. `nginx -g`에는 main 컨텍스트 지시자만 가능. `events {}`/`http {}` 블록은
   `-g`로 전달 불가 → emerg 종료. **수정: nginx.conf 파일 생성 후 bind-mount**
   (`-v .../nginx.conf:/etc/nginx/nginx.conf:ro`, 이미지가 기본 `daemon off`).
2. `proxy_pass http://spark2:8188`의 `spark2`가 resolve 불가.
   **수정: CX7 노드명 `spark2-p1-r0`을 resolve → 192.168.102.2를 `proxy_pass`에 직접 기재.**
   이름이 나중에 mgmt LAN으로 바뀌어도 오경유하지 않는다.
3. ComfyUI는 웹소켓(`/ws`) + 수십 분짜리 생성 폴링을 쓴다.
   **수정: `Upgrade`/`Connection` 헤더 + `proxy_read/send_timeout 3600s` +
   `client_max_body_size 0` + `Host`/`X-Real-IP` 헤더.**
   (기본 60s 타임아웃이면 장시간 생성 중 ws가 끊긴다.)

추가 안전장치: resolve된 IP가 `CX7_SUBNET` 대역이 아니면 스크립트가 중단된다
(mgmt 192.168.1.x 오지정 시 `FAIL` + 종료).

## 4. 변경 파일

신규: `h3.cluster.env`, `infra/dgx-spark-1/service/nginx/proxy-up.sh` (+ 런타임 `infra/dgx-spark-1/service/nginx/proxy-8188/`,
`.gitignore` 등록). `nginx:alpine`은 proxy-up 최초 실행 시 pull됨 (동작 확인済).

수정: 전 스크립트 주요 명령을 `(set -x; <cmd>)` 래핑 —
실패 시 실행된 명령이 그대로 echo되므로 로그만으로 원인 추적 가능.
각 스크립트 맨 뒤 자체 검증은 기존 유지 (health 대기, `system_stats` 200,
`docker images`, 산출물 `ls`/`ffprobe`, 상태 요약).

## 5. 배포 절차 요약 (상세: `h3.instruction.txt`)

- Phase 0: 양쪽 `git pull`, spark1에서 CX7 이름 확인
- Phase 1: 박스별 preflight (spark1은 proxy 기동 전에 실행 — 8188 WARN 회피)
- Phase 2: spark1 `2-download.sh all` (270G, 수 시간) ∥ spark2 소스→빌드→모델
  (텍스트 인코더 중단분은 hf가 resume)
- Phase 3: spark1 FL2VA 서빙+smoke ∥ spark2 Comfy 기동+torchaudio fix+첫 영상
- Phase 4: spark1 `proxy-up.sh` (자체 검증: 경유 `system_stats` 200)
- Phase 5: 교차 검증 — spark1 경유 200 vs spark2 직통 200, `:8000/health`

## 6. 운영 룰

- 서빙 중에는 반대편 박스 포함 **대용량 다운로드·빌드 금지**
  (9/30 다운 원인이 서빙 중 병행 다운로드 정황).
- spark1은 FL2VA/Ref2VA 중 하나만. 갈아탈 때 `8-stop-vllm.sh` 선행 (스크립트 내장).
- 감시용: `journalctl -k -f | grep NVRM` (NO_MEMORY 재발 시 즉시 중단·원인 파악).
- ComfyUI 풀 해상도 전에는 608x352 스모크부터.

## 7. 장애·롤백

- proxy 이상: `docker logs proxy-8188` → 502면 spark2 Comfy 미기동,
  타임아웃이면 패브릭 단절 (`getent hosts spark2-p1-r0` 재확인).
  롤백: `docker rm -f proxy-8188` (spark1:8188이 비워지고 직통만 남음).
- 한쪽 박스 다운: 남은 쪽 단독 운용으로 전환 (그때는 1대 룰=동시 금지 재적용).
  스크립트가 양쪽에 그대로 있으므로 역할 이전 가능.
- Comfy 모델 불완전 시 `4-download.sh fl2va` 재실행 (resume, 서빙 중지 상태에서만).
