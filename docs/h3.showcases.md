# H3 쇼케이스 카탈로그 (spark1 vLLM + spark2 ComfyUI)

한 클립 4~15초, 24fps, 네이티브 스테레오 32kHz가 전제.
"완성 1편"이 아니라 "클립 체이닝 → 편집"이 단위다 (장편 전략은 §4).

## 0. 산출물 레이아웃 (적용됨)
- Primary (리포): `results/<showcase-slug>/profiles/<quality-profile-slug>/`
  (generate.sh, shots/, `<showcase-slug>.mp4`)
- Secondary (공유 NAS): `/rosenas/data/AIML/video-generation/results/` —
  `./sync-results.sh`로 동일 트리 incremental 복사 (NAS_DEST로 변경 가능)
- quality-profile: `preview` (STEPS=10), `full` (STEPS=50) — 동일 스크립트, STEPS 기본값만 다름
- github 업로드는 **Git LFS** 확정. **모든 mp3/mp4 및 비디오·오디오 파일**을 LFS track
  (리포 루트 `.gitattributes`). `git lfs install` 후 적용.
  timings.csv 같은 텍스트 기록은 일반 파일로 유지.

## 3. ComfyUI 템플릿 대응 (spark2, Template Library > Video)

T2V / I2V / R2V(=Reference) 3종. 기본 20스텝, Turbo LoRA 8스텝 맛보기 가능
(오디오·모션 품질 소폭 하락). 네이티브 1344x768, 608x352=스모크.
- 검증済み: `showcase/t2v_first.json` (공식 T2V 템플릿을 API 포맷·turbo8·608x352로 수동 변환,
  matchgirl 1번샷 동일 프롬프트) → `matchgirl/comfy_first_00001_.mp4` 5.17s, h264+AAC stereo.
  주의: 공식 템플릿의 video VAE는 int8_convrot이나, 실행 검증은 fp16 VAE로 통과
  (GB10 unified 128G라 VRAM 여유로 무관).

## 4. 장편(5분+) 전략 — 클립 체이닝이 본체다

단일 생성으로 5분을 뽑는 모델은 없다 (토킹헤드 아바타 제외).
실전 파이프라인은 전부 "짧은 클립 + 정합성 + 편집"이다:

1. **캐릭터 바이블 고정**: 전신/측면/표정 레퍼런스 팩 1회 생성 후 재생성 금지
   (H3는 최대 9이미지·3비디오·3오디오 레퍼런스 지원 — R2VA에 그대로 투입)
2. **매 샷 I2V/FL2VA로 시작**: 텍스트 첫 프레임이 아니라 canonical 이미지에서 출발
3. **프레임 체이닝**: clip N 마지막 프레임(ffmpeg 추출, `7-demo-ref2va.sh` 방식)을
   clip N+1 첫 프레임으로. 3~4클립마다 원본 레퍼런스 팩으로 리프레시 (드리프트 누적 방지)
4. **오디오 포스트 분리**: 대사/SFX/음악을 별도 트랙으로 (H3 네이티브 오디오는 초안용)
5. **편집·그레이드** 후 조립
